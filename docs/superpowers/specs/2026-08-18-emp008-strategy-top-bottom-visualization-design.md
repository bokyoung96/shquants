# EMP008 전략별 Top/Bottom 시각화 설계

## 목적

기존 합의점수 그림은 9개 팩터 가중치 후보를 합산하므로, 어느 전략에서 WI26와 WICS의 종목 선택이 달라졌는지 직접 확인하기 어렵다. 2020년 이후 각 전략을 독립적으로 비교할 수 있는 요약 그림과 전략별 상세 그림을 만든다.

## 비교 대상

- 기간: 2020-01-01 이후 사용 가능한 마지막 리밸런싱일까지
- 분류: WI26, WICS
- 전략: 두 결과에 공통으로 존재하는 9개 후보
- 종목 선택 기준: 기존 산출물의 Active 비중 기준 Top 10과 Bottom 10
- 전략 표기: 후보 ID와 네 팩터 가중치를 함께 표시
  - `s`: Size
  - `m`: 12개월 모멘텀
  - `e`: 영업이익 컨센서스
  - `v`: FCF/TEV

## 산출물 1: 전체 전략 차이 요약

세로축은 9개 전략, 가로축은 월별 리밸런싱일인 히트맵을 만든다. 각 셀은 다음의 정수값을 표시한다.

```text
Top 교체 수 = 10 - WI26 Top 10과 WICS Top 10의 공통 종목 수
Bottom 교체 수 = 10 - WI26 Bottom 10과 WICS Bottom 10의 공통 종목 수
전체 교체 수 = Top 교체 수 + Bottom 교체 수
```

전체 교체 수의 범위는 0~20이다. 0은 WI26와 WICS의 Top/Bottom 목록이 모두 같다는 뜻이고, 20은 양쪽 목록에 공통 종목이 없다는 뜻이다. 후보 간 합산점수나 수익률 비율은 사용하지 않는다. 연도 경계선을 표시하고, 차이가 큰 셀은 진한 색으로 표현한다.

## 산출물 2: 전략별 상세 그림 9장

전략마다 WI26와 WICS를 좌우 패널로 배치한다. 행은 종목, 열은 월별 리밸런싱일이며 셀 값은 다음과 같다.

- `+1`: 해당 전략에서 Top 10
- `-1`: 해당 전략에서 Bottom 10
- `0`: 해당 월의 Top/Bottom 목록에 없음

빨강은 Top, 파랑은 Bottom, 흰색은 미등장으로 통일한다. 두 패널은 동일한 종목 행과 날짜 열을 사용한다. 한 장에는 2020년 이후 반복 등장 강도가 큰 Top 종목 15개와 Bottom 종목 15개를 공통 선정해 최대 30개를 표시한다. 동률은 종목코드 오름차순으로 고정해 실행할 때마다 결과가 달라지지 않게 한다.

각 제목에는 후보 ID와 실제 팩터 가중치를 한글로 표시한다. 예시는 다음과 같다.

```text
s50_m30_e10_v10
Size 50% · 12개월 모멘텀 30% · 영업이익 컨센서스 10% · FCF/TEV 10%
```

## 원자료

그래프에서 생략된 저빈도 종목도 확인할 수 있도록 다음 CSV를 저장한다.

- 전략·리밸런싱일별 Top 교체 수, Bottom 교체 수, 전체 교체 수
- 전략별 WI26 종목 상태 행렬
- 전략별 WICS 종목 상태 행렬

상태 행렬에는 그림에 표시된 30개뿐 아니라 2020년 이후 한 번이라도 Top/Bottom에 등장한 모든 종목을 포함한다.

## 구현 경계

기존 `factor_weight_top_bottom_plots.py`의 엑셀 입력 및 한글 폰트 처리 패턴을 재사용한다. 합의점수 산출물은 삭제하지 않고 기존 분석 재현을 위해 유지한다. 새 전략별 산출물은 별도 하위 폴더에 생성해 기존 결과를 덮어쓰지 않는다.

## 오류 처리

- WI26와 WICS의 전략 집합이 다르면 공통 전략만 조용히 사용하지 않고 불일치 전략을 명시한 오류를 낸다.
- 특정 전략의 날짜 집합이 다르면 공통 날짜만 사용하지 않고 누락 날짜를 명시한 오류를 낸다.
- 어느 한쪽에 Top 또는 Bottom 10이 정확히 10개가 아니면 해당 전략·날짜를 명시한 오류를 낸다.
- 2020년 이후 데이터가 없으면 산출물을 만들지 않고 오류를 낸다.

## 검증

- 작은 인공 데이터로 교체 수가 정확히 계산되는지 단위 테스트한다.
- 전략 필터가 다른 전략 행을 섞지 않는지 검증한다.
- WI26/WICS 전략 및 날짜 불일치가 오류로 처리되는지 검증한다.
- 실제 두 워크북으로 요약 PNG 1개, 전략별 PNG 9개와 CSV가 생성되는지 확인한다.
- 관련 EMP008 테스트를 함께 실행해 기존 합의점수 보고서에 회귀가 없는지 확인한다.
